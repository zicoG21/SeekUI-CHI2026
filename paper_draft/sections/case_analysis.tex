\section{Case Analysis}

The quantitative results show the size of the improvement, but the case analysis explains what kind of behavior changes. The real-absent case analysis shows where the verifier helps and where it fails. On the 100-example validation set, combined AND corrects 15 prompt-only mistakes, introduces 6 new present false-absent errors, and leaves 1 absent false-present error.

The broader mined taxonomy in Figure~\ref{fig:error_taxonomy} suggests the same tradeoff: the verifier removes many weak-evidence forced-choice errors, but present false-absent errors concentrate on small, peripheral, low-contrast, or cluttered targets. Figure~\ref{fig:representative_cases} shows three representative patterns. In a corrected absent false-present case, prompt-only SeekUI predicts present, while combined AND rejects it because both path and OCR evidence are weak. In a new present false-absent case, a visible target is weakly supported by the generated path and OCR, so the conservative verifier over-rejects it. In a residual absent false-present case, strong distractors leave enough evidence for the verifier to keep the prompt-only present decision.

\paragraph{Corrected absent false-present cases.}
These cases support the forced-choice interpretation. Prompt-only SeekUI often commits to a plausible but weakly supported region. The combined verifier rejects many of these cases because neither the path evidence nor the OCR evidence supports the requested target.

\paragraph{New present false-absent cases.}
The main cost of the verifier is conservative rejection. These errors are not random: they concentrate on small, edge-positioned, stylized, low-contrast, or cluttered targets. This suggests that future methods should improve candidate generation and visual evidence, not only tune thresholds.

\paragraph{Residual absent false-present cases.}
The kept errors are harder. They often contain strong text, button, icon, or function distractors that overlap with the target cue. These residual cases motivate evidence-aware VLM verification and richer UI semantics.
