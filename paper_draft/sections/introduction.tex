\section{Introduction}

GUI visual search is not only a localization problem. In real interfaces, users often search for controls, settings, links, or actions that may not be present on the current screen. A user may look for a submit button before completing a required field, search for a privacy setting inside the wrong menu, or expect a familiar action that the current screen does not expose. In these situations, a system that is forced to always return a target can hallucinate plausible UI elements and create unsafe or misleading interaction traces.

This paper studies that gap through the SeekUI pipeline. SeekUI-style models predict visual search behavior under the assumption that the requested target exists in the screenshot. That assumption is reasonable for target-present scanpath benchmarks, but it hides a practical failure mode: when the target is absent, the model may still behave as a forced-choice grounding system and commit to a semantically or visually plausible distractor.

The central question is therefore whether scanpath and UI evidence can help a target-present model make a stopping decision. Rather than asking only where the model looks, we ask whether the model has enough evidence to say that the target is present at all.

We therefore use the following research question:

\begin{quote}
Can scanpath and UI evidence help GUI visual search models decide when to stop and report target absence, instead of forcing every query to ground to a UI element?
\end{quote}

The core claim is simple: target-absent GUI search benefits from explicit evidence accumulation. We test three forms of evidence: scanpath-based cognitive stopping, OCR candidate matching, and a VLM verifier that sees the screenshot together with path/OCR evidence.

The current results support three empirical points. First, prompt-only SeekUI shows a forced-choice failure mode on target-absent trials. Second, a combined path+OCR verifier substantially reduces absent false-present errors on a held-out image split. Third, full-benchmark VLM comparisons suggest that screenshot reasoning and scanpath/OCR evidence are complementary, with the same combined-verifier trend appearing in a small realistic absent validation set.

This paper makes four contributions:

\begin{enumerate}
  \item We formulate target-absent GUI visual search as an uncertainty-aware extension of target-present scanpath prediction.
  \item We construct a synthetic present/absent stress test from the released SeekUI/VSGUI subset and audit its label and OCR artifacts.
  \item We introduce post-hoc stopping and verification layers that use scanpath evidence and OCR evidence without retraining SeekUI.
  \item We provide quantitative, behavioral, qualitative, and small realistic-validation evidence that target-absence handling is not merely a thresholding detail, but a distinct failure mode of forced-choice GUI grounding.
\end{enumerate}
